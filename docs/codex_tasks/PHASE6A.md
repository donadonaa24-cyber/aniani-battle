# PHASE 6A 指示書：操作の分かりやすさ・方向別攻撃・スタミナ・勝敗ポーズ（Claude → Codex）

## ユーザーの実機プレイ後の感想（2026-10-12、PS5コントローラー使用）
> 初期にしてはかなりの完成度だけど、まだまだ足りない。
> - **単純に操作が分かりにくい**
> - **空中攻撃・しゃがみ攻撃・後ろ攻撃を使いたい**
> - **スタミナを追加していい**。ずっと逃げ回ることはないと思うが、スタミナがあれば「スタミナが多いキャラ」など今後の差別化ができる。ジャンプするのにスタミナをいくら使う、など。
> - 滑らかさとテンポは今はこれでよい（後で修正したい）。
> - **勝ち負けの後のキャラの動きが激しすぎて違和感がある**（座り込む・やったぁと喜ぶなど、ポーズが違い過ぎてカクカクする）。**ほとんど動かない程度のポーズでよい**。そうすればカクカクしないかも。

## ★ 追加のユーザー決定（2026-10-12、原本ルールの一部を変更。最優先で従う）
ユーザーが原本の確定ルールの一部を変更した。`GAME_DESIGN.md` に「ユーザー決定による変更（2026-10-12）」として、**旧ルール → 新ルール**を明記すること。原本 `docs/SPEC_ORIGINAL.md` は書き換えない（履歴として残す）。

1. **空中攻撃に左右・斜めを追加**：現在の空中攻撃は「その場にとどまる上下攻撃」しかない。空中で **前（横）・後ろ・上・下・斜め前上・斜め前下**（＋ニュートラル）を出せるようにする。斜めはスティック／十字の斜め入力（キーボードは2キー同時）。空中技の一部は**前方への移動を伴う**（その場で止まらない）。斜め入力の判定しきい値と、斜め技が無い場合のフォールバック（近い方向の技）をデータ化。
2. **ガードはスタミナを消費する。ガードは通常攻撃・特殊攻撃・超必殺技のすべてを防げる**（旧：通常攻撃はガード不可、超必殺は通常ガード不可）。
   - ガード中は毎秒少しずつスタミナを消費し、**防いだ瞬間に攻撃の種類に応じてスタミナを消費**（例：通常 小、特殊 中、超必殺 大。データ化）。
   - **スタミナが足りないとき：超必殺技はガードを貫通**して通常どおり命中（ハート2）。通常攻撃・特殊攻撃でスタミナが尽きた場合の扱いも決める（推奨：ガードが崩れて短い硬直＝ガードブレイク。命中扱いにはしない）。
   - ジャストガードは引き続き有効（スタミナ消費を小さく／ゼロにする等、ジャストの価値を残す）。
3. **しゃがみ攻撃（↓＋攻撃）はガード崩し**：ガード中の相手に当たると、**ガードを崩して被弾カウント+1（ハートの1/3）**。崩された側は短時間ガード不能（データ化）。しゃがみ攻撃は通常攻撃扱い（ガードされていない相手には通常どおり+1、コンボ・カウンターの対象）。
   - これにより原本の相性「通常攻撃 → ガードに勝つ」は「**しゃがみ攻撃 → ガードに勝つ**」に変わる。相性表を更新。
4. 上の変更に合わせて：**相性表、CPU（ガードの使い方、しゃがみ攻撃でガードを崩す、スタミナ管理）、チュートリアル（ガード・ガード崩し・スタミナの段）、技表、テスト**を更新。旧ルール前提のテスト（「通常攻撃はガードを貫通」「超必殺は通常ガード不可」等）は、新ルールのテストに**置き換える**（削除ではなく、新ルールを検証する形に書き換え、置き換えた一覧を報告）。
5. バランス：ガードが強くなりすぎて試合が長引かないよう、PHASE5B の目標（ふつう同士の平均決着 35〜55 秒、縮小到達 20〜40%、超必殺は半数前後）を維持。必要ならガードのスタミナ消費・回復で調整。

前提：フェーズ5B まで Claude が Unity 検証済み（EditMode 243/243、PlayMode 23/23、ビルド成功）。GitHub 公開リポジトリ `donadonaa24-cyber/aniani-battle` に初回コミット済み。**Unity 全合格の区切りで commit・push してよい**（AGENTS.md 参照）。

## 1. 方向別の通常攻撃（原本のルールに組み込む）
- 追加する通常攻撃（すべて **Kind=Normal**：ガード不可・被弾蓄積+1・3ヒットでハート-1・最大3ヒットコンボ・コンボフィニッシュ対象。原本の確定ルールは変えない）：
  - 地上：**弱（既存の3段）**／**しゃがみ攻撃**（↓＋攻撃：低い姿勢の足払い系。発生早め・リーチ短め）／**後ろ攻撃**（←（背後方向）＋攻撃：振り向きながら背後を打つ。発生やや遅め）／（任意）上攻撃（↑＋攻撃：対空）
  - 空中：**空中ニュートラル**／**空中前**／**空中後ろ**／**空中上**／**空中下**（下は着地隙大きめ。メテオ（叩き落とし）にするなら場外即敗北ルールとのバランスに注意し、強すぎないように）
- **しゃがみ状態**を追加：地上で↓を押している間はしゃがみ（Hurtbox を低く、移動不可）。すり抜け足場の上では「↓長押し」または「↓2回」で降りるなど、しゃがみと足場降りが衝突しない操作にする（決めた操作を `GAME_DESIGN.md` に）。
- 入力の解釈：方向は**キャラの向き基準**（前／後ろ）。空中でも向きは変わらない（空中後ろ攻撃が成立する）。同時押しの優先順位表を更新。
- カウンター：近距離通常攻撃の判定（`IsCloseRange`）を各技に設定。
- データ：すべて `AttackData`（キャラごと）。3キャラで性能差（透真＝発生が早く隙が少ない、蓮＝リーチと突進力、千鶴＝判定が大きめ・変則、など）。数値は `BALANCE_CONFIG.md` に表で。
- アニメ：各キャラに **crouch（しゃがみ待機）・crouch_attack・back_attack・（up_attack）・air_neutral・air_forward・air_back・air_up・air_down** を SpriteForge で追加（画像生成で描く。**前後のコマを重ね合わせる中割りは禁止**：`docs/REVIEW_NOTES.md` フェーズ5B節参照）。品質が足りないコマは作り直す。

## 2. スタミナ（新しいルール：ユーザー承認済みの追加仕様）
- `GAME_DESIGN.md` に **「ユーザー承認の追加仕様（2026-10-12）」** として明記。原本の確定ルール（ハート・蓄積・コンボ・相性・超必殺・場外・縮小）とは独立。
- シミュレーション（`AniBato.Battle`、決定的）に `StaminaSystem`：
  - キャラごとの **最大スタミナ・回復速度・回復開始までの遅延**（`CharacterData`）。
  - 消費（データ化・初期値の目安）：ジャンプ 8、2段ジャンプ 12、地上ダッシュ開始 8、空中ダッシュ 14、回避 18、（任意）ガード中は毎秒少し減る。攻撃・特殊・カウンター・超必殺は消費しない（戦闘の読み合いを壊さない）。
  - 足りない時：その行動ができない（入力は無視され、HUD のスタミナが赤く点滅）。
  - **復帰の救済**：場外近くでの「上必殺技（復帰技）」はスタミナ不足でも使える。1段目ジャンプは地上なら常に可能など、**スタミナ切れで理不尽に場外負けしない**こと（テストで保証）。
  - 回復：地上で行動していない間に速く、空中・行動中は遅い（データ）。
- 3キャラの初期差（目安。理由も記録）：透真＝回復が速い、蓮＝最大は少ないが消費が少ない（機動型）、千鶴＝最大が多い（持久型）。
- HUD：ハートの下にスタミナバー（色・数値）。キャラの足元にも小さなバー（任意、設定でOFF可）。
- CPU：スタミナを考慮（切れそうなら無理に追わない、復帰用に残す）。
- バランス：PHASE5B の目標（ふつう同士の平均決着 35〜55 秒、縮小到達 20〜40%、超必殺は半数前後、自滅ほぼ0）を維持。`docs/CPU_BALANCE_REPORT.md` を再集計。

## 3. 操作を分かりやすく
1. **練習モード（トレーニング）**：メインメニューに追加。CPU 相手が「棒立ち／ガードし続ける／ジャンプし続ける／ふつう CPU」から選べる。ハート・時間は減らない（設定で切替）。画面に**入力表示**（押したボタンと方向）と、出した技の名前を表示。
2. **チュートリアル**（練習モード内 or 独立）：段階ごとに課題を出してクリアで次へ。移動→ジャンプ/2段ジャンプ→通常3段→方向攻撃（しゃがみ・後ろ・空中）→特殊4方向→ガード（特殊を防ぐ）→回避→カウンター（近距離通常に勝つ）→ジャスト防御→超必殺→スタミナ→ルール（ハート3、被弾3でハート-1、場外、最後10秒の縮小）。各段に短い説明文と、**その時使っている入力デバイスのボタン表記**。
3. **技表（コマンドリスト）**：ポーズ画面とキャラ選択から開ける。キャラごとに全技（方向攻撃・特殊4種・超必殺・カウンター効果）の入力と一言説明。
4. **ボタン表記の自動切替**：DualSense／PlayStation 系なら × ○ □ △ L1 R1 L2 R2 OPTIONS、Xbox 系なら A B X Y LB RB LT RT、キーボードならキー名。操作説明・チュートリアル・技表・画面下のヒントすべてに適用。（ユーザーは PS5 コントローラーを USB 接続で使用）
5. **キーコンフィグ**：各アクションのボタンを変更・初期化。キーボード／パッド別、P1/P2 別。ローカル保存（PlayerPrefs 等）。重複時の扱いを決める。
6. **対戦中の常時操作表示は撤去**（画面下の長い操作表）。代わりに、開始直後の数秒だけ小さな基本操作ヒント（設定でOFF）。
7. 操作体系の見直し提案：分かりにくさの原因を自分で分析し（ボタン数、ダッシュの出し方、特殊の方向入力など）、**変えた方がよい点を `docs/CONTROLS_REVIEW.md` に提案**（実装は分かりやすさが明確に上がるものだけ。大きく変える場合は Claude/ユーザー確認待ちとして残す）。

## 4. 勝敗ポーズを控えめに
- win / lose アニメを **idle を基準にした小さな差分**（姿勢はほぼ同じ、表情・手・頭の角度・呼吸の上下 1〜2px 程度）に作り直す。座り込み・大きなガッツポーズはやめる。KO 時のアニメ（倒れ）は別でよいが、急な姿勢の飛びが無いこと（中割りは画像生成）。
- リザルト画面・試合終了時の両方で使用。preview GIF を出力。

## テスト
- 方向攻撃：入力→技の選択（向き基準、空中後ろ）、各技が Normal 扱い（ガード不可・蓄積・コンボ・カウンター対象）、しゃがみの Hurtbox、足場降りとの非衝突。
- スタミナ：消費・回復・不足時に行動不可・**復帰の救済で理不尽な場外負けが無い**・決定性（30/60/144/240Hz）。
- チュートリアルの各段の判定、ボタン表記の切替（DualSense と Xbox のテスト用デバイスで）、キーコンフィグの保存・初期化・重複処理。
- 既存の必須テスト1〜24相当と全既存テストが通ること。
