# 配布容量の調査・最適化・比較・公開（2026-10-23）

所有者指示：ゲームシステムを壊さず、画質を可能な限り保ち、未採用素材を配布へ含めず容量を削減する。調査→効果順に修理→再ビルド比較→動作確認。

1. 現行のWindows ZIP509049136bytes/展開2520696705bytes、Android161961932bytes、Web138814613bytesを基準として保存。BuildReportとシーン依存関係を調べ、採用/予備/未参照の画像を区別する。
2. 最初はWindowsへビルド時だけの旧姿勢/旧背景/カバン参照除外を適用し、LZ4HC可逆圧縮を使用。原PNG、採用原画、旧素材・カバン予備、ゲームData、当たり判定を編集/削除しない。Windows画像は元のRGBA品質を保つ。
3. 実BuildReportの素材別容量/依存関係とビルド出力を監査。Web/Androidの現行GPU圧縮・原画保持を踏まえて、効果があり画質を維持できる追加削減を選ぶ。巨大な中間生成物を配布ZIPへ追加しない。
4. 影響するビルド複製処理はEditModeで元データ不変/採用ポーズ・投射・演出・支点の保持を検査。実Unity全4と再ビルド、容量比較、描画/起動確認を実施。テストのアサーションを弱めない。
5. 小さくなり同等動作を確認できた配布物を新しい試作Releaseへ公開し、ポータルを更新する。既存配布は上書きせず再現可能に保管する。Web/Androidは改善の実測がある場合だけ差し替え、不利な場合は現行版を維持する。
6. 数値、画質確認、動作確認、変更しなかったもの、未確認事項をRESUME/IMPLEMENTATION_STATUS/検証JSONに記録する。

Unity実行とビルドは順次行う。同時編集は禁止。既存の未コミット生成画像/2シーンは破棄せず保持する。

## 比較による追加方針

可逆版は展開2.52GB→602MBだがZIP509MB→474MBで、配布の削減は約7％。原寸BC7最高品質も比較する。312画像の原寸GPU誤差・324スプライトの支点/範囲を検査し、PSNR35dB未満の画像・旧ピクセル素材は元形式を維持する。測定合格305画像のSHA付き許可表をWindowsTextureQualityPolicy.jsonへ保存し、残り7画像と新規/変更/未測定画像は元形式に戻す。

Windowsは元のフィルタ/ミップ設定を維持する。Web/Android向けのミップ設定をそのまま転用してぼかさない。ビルド時の形式切替をUnityキャッシュが認識しない場合があるため、CleanBuildCacheで実際の参照/画像形式を再構築する。原PNGは変更しない。最終形式は完全可逆ではなく、305画像が高品質BC7・7画像が元形式・データ保存が可逆LZ4HCであることを報告する。
