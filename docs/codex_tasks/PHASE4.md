# PHASE 4 指示書：ステージとゲーム進行（Claude → Codex）

ユーザー判断（2026-10-12）：**透真の目元・蓮の見づらさの手直しは後回し**にし、先にフェーズ4へ進む。ART2 のスプライトはそのまま使う。

原本：`docs/SPEC_ORIGINAL.md` 6章（ステージ）・8章（画面）・12章（テスト16〜18・22）。
完了の定義：**タイトルから起動して、キャラ選択 → ステージ選択 → 対戦 → リザルト → 再戦／キャラ選択へ戻る、が実際に遊べること**。

## 1. ステージ縮小（ゲームルール。最優先）
- シミュレーション側（`AniBato.Battle`、純C#）に `StageShrinkController`（名前は任意）を追加し、**60Hz tick で決定的に**床を縮める。描画はその状態を読むだけ。
- タイミング（データ化、`BattleRules` or `StageData`）：
  - 開始 55秒（残り15秒）で**予告**イベント（`StageShrinkWarning`）→ 演出側が警告表示
  - 開始 60秒（残り10秒）で**縮小開始**（`StageShrinkStarted`）
  - 残り10秒の間に、メイン足場の左右端が**段階的に**内側へ消える（例：5段階、各段の直前 1.0秒は点滅予告 → 消滅）
  - 最後は**中央の小さな足場のみ**（幅データ化、例：主足場の 25〜30%）
  - 上部の小足場2つの扱いも決める（例：2段階目で消す）。決めた内容を `GAME_DESIGN.md` に暫定仕様として記録。
- 理不尽にしない：消える区画の上にいるキャラには必ず予告時間がある。消えた区画の上のキャラは落下するだけ（即死ではない）→ 場外ライン超えで敗北（既存ルール）。
- 当たり判定・タイミングは**3ステージ共通**。背景演出（下記）とは分離。
- テスト（EditMode）：必須テスト17「残り10秒で縮小開始」、予告→消滅の順序、最終形が中央足場のみ、縮小で足場を失ったキャラが落下して場外負けになる、縮小は時間切れ判定と矛盾しない（必須テスト18「残り0秒で正しく勝敗」）。

## 2. 3ステージ（見た目のみ差し替え、地形は共通）
- `StageData` に「見た目テーマ」（背景、床・足場の色/テクスチャ、縮小演出の種類、BGMキー）を持たせ、地形（`StageGeometry`）は共通の1つを参照。
- STAGE 01「星の終わり」：管理AIが支配する近未来都市（青・紺・電子的な光・未来建造物、遠景に打ち上げタワーのような塔があってもよい）。縮小演出：AIの警告表示（例：「AREA RESTRICTION」等の電子文字）＋電子的に消える。
- STAGE 02「推し駒Battle」：原作の6×6盤面をイメージした闘技場（盤面の床、巨大な駒、階層塔）。縮小演出：盤面の外側のマスが消えていく。
- STAGE 03「Battle à la carte」：文化祭の調理場（屋台、調理道具、料理、文化祭の装飾）。縮小演出：文化祭終了（照明が落ちる・片付けられる等）。
- 背景は**レイヤー構成**（遠景・中景・床）で、軽い視差スクロール程度。画像生成で作ってよい（**原作素材を使う場合は `docs/ASSET_SOURCES.md` に出典**。推し駒の盤面の雰囲気は `%USERPROFILE%\\OneDrive\デスクトップ\あにあにの遊び場\images\oshikoma-board.jpg` 等を読み取り専用で参考可）。背景がキャラより目立って見づらくならないよう、彩度・明度を抑える。
- 将来の昼・夕・夜差分に対応できるよう、テーマを差し替え可能な構造にする（今回は1種類でよい）。
- 背景に時間をかけすぎない（優先順位は ゲームルール ＞ 画面遷移 ＞ 背景の豪華さ）。

## 3. 画面とゲーム進行
- シーン構成は任意（1シーン内のUI切替 or 複数シーン）。`ProjectBuilder.BuildAll` で生成し Build Settings に登録。起動シーンは**タイトル**。
- 画面：
  1. **タイトル**：「あにあにバトル！！」ロゴ（テキストでよい）、Press Any Key
  2. **メインメニュー**：CPU対戦／2人対戦／操作説明／終了
  3. **キャラ選択**：透真・蓮・千鶴（立ち絵 or idleスプライト＋名前＋出典作品名＋一言タイプ説明）。P1/P2 それぞれキーボード／パッドで選択。CPU対戦では P2 側に CPU難易度（やさしい／ふつう／むずかしい）を選ぶ欄だけ用意（CPU本体はフェーズ5。今回は選択値を保持するだけで、P2は動かない or 立っているだけでよい）。
  4. **ステージ選択**：3ステージ（サムネ＋名前）、ランダム可。
  5. **対戦**：既存の Battle。カウントダウン（3,2,1,FIGHT）を追加。
  6. **ポーズ**（Esc／パッドStart）：再開／操作説明／キャラ選択へ／タイトルへ。ポーズ中はシミュレーション停止（tick を進めない）。
  7. **リザルト**：勝者（キャラの win アニメ）・敗者（lose アニメ）、決着理由（KO／場外／時間切れ判定／引き分け）、「再戦」「キャラ選択へ」「タイトルへ」。
  8. **操作説明**：P1/P2 キーボード、ゲームパッドの表、基本ルール（ハート3、被弾3でハート-1、通常はガード不可、特殊はガード可、超必殺など）を簡潔に。
- 既存の「試合終了後 F1〜F4 でキャラ切替・Rで再戦」の仮手段は、正式画面ができたら削除してよい（テストも正式画面に合わせて更新）。
- 画面はキーボード・ゲームパッドの両方で操作できること（マウスは任意）。1920×1080基準、他の比率でも崩れない（CanvasScaler）。
- テスト（PlayMode）：必須テスト22「リザルトから再戦」、タイトル→メニュー→キャラ選択→ステージ選択→対戦開始の遷移、ポーズでtickが止まる。
