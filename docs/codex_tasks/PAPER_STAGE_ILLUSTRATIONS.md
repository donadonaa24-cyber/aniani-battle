# 3ステージを生成イラストの紙舞台に作り直す（2026-10-15、Claude記入）

## ユーザーの依頼
> ステージはユニティの素材で無理やり作ってるからあんまりいい感じじゃなくて、もっとペーパー感を出したい。生成イラストを使ってそれぞれのステージに組み込みたい。

現状（0bbc2b6）：`StageBackgroundView` / `PaperStageScenery` が Unity の単色図形・テキストで工作舞台を組んでいる。これを **生成イラスト（透過PNGのレイヤー）** に置き換える。

着手条件：他の作業（透真の基礎ポーズ等）の区切り後。同時編集禁止。**ゲームルール・当たり判定・縮小のタイミング／段数は一切変えない**（見た目だけ）。

## 共通地形（変えない。絵はこれに合わせる）
`Data/CommonGeometry.asset`：メイン足場 幅36（中心 x=0）、上の小足場2つ 幅7（中心 x=±8、下から通過可）、左右・下に場外線。縮小は左右から段階的に消え最後は中央の小足場のみ（既存 `StageShrinkController` の区画に合わせる）。

## 1. 生成するレイヤー（各ステージ同じ構成）
| # | レイヤー | 形式 | 用途 |
|---|---|---|---|
| L1 | 遠景（空・遠い街並み等） | 横長 3840×1600、不透明 | 最奥。視差 0.15 |
| L2 | 中景（建物・舞台装置の書き割り） | 3840×1600、**透過** | 視差 0.4 |
| L3 | 舞台枠（左右の袖幕・上の看板） | 3840×2160、**透過**（中央は空ける） | 画面固定の額縁。キャラと足場を隠さない |
| L4 | メイン足場 | 横長の帯 3600×360、**透過** | 幅36の足場に1:1で貼る。上端が足場の天面 |
| L5 | 小足場 | 720×200、**透過** | 幅7の小足場2つに使用 |
| L6 | 縮小用の区画ピース | メイン足場を **縮小の区画ごとに分けた透過パーツ**（L4から切り出すか、区画単位で生成） | 消えるときは区画ごとに「めくれる／倒れる／破れる」紙演出 |
| L7 | 縮小の演出物（ステージ固有） | 透過の小物 2〜4枚 | 下記の作品別 |

- 画風：**厚紙・切り絵の舞台セット**。キャラは普通のアニメ塗りなので、背景は彩度と明度を一段落としてキャラを目立たせる。紙の縁（白い切り抜き縁）、少しずれた重なり、紙の厚みの影（短く固い影）で「紙を貼り重ねた舞台」に見せる。
- 文字は入れない（看板は無地 or 記号）。ロゴ・既存作品の固有デザインを複製しない。
- 透過は本当の透明背景。足場の天面のラインは水平でまっすぐ（足元の判定とずれないように）。

## 2. 作品別の内容（プロンプトに入れる要素）
### STAGE 01 星の終わり（青・紺・電子光）
- L1：夜明け前の紺色の空と星、遠くの未来都市のシルエット、遠景に打ち上げタワー。

- L7（縮小）：赤い警告ランプの紙細工、区画が「デジタルにほどける」ための四角い紙片の束。
### STAGE 02 推し駒Battle（6×6将棋風盤）
- L1：あたたかい木目の闘技場の壁、遠くに階層の塔。

### STAGE 03 Battle à la carte（文化祭の調理場）
- L1：秋の夕方の校舎と空、遠くに模擬店の旗。

- L3：紅白の幕、上部に無地の手書き看板風の厚紙。
- L4：調理台・木のテーブル天板の足場。L5：まな板の形の小足場。
- L7（縮小）：「本日終了」の雰囲気の、片付けられる紙皿・たたまれる旗（文字なし）、照明が落ちる表現用の暗幕片。

## 3. 生成プロンプト（コピーして使える。Web の画像生成でもそのまま使用可）
共通の頭書き（各プロンプトの先頭に付ける）：
```
オリジナル対戦ゲーム『あにあにバトル！！』のステージ用背景素材。厚紙と切り絵を貼り重ねた「紙の舞台セット」の画風。手で切った紙の縁、全外周に細く（原画で3〜6px程度）くっきりした薄いクリーム白の切り抜き縁。縁はぼかさず、外側へのにじみ・グロー・光彩・ぼかし影を付けない。縁の外は完全な透明、紙を数ミリ浮かせたような短く固い影、少しずれた重なり。色は落ち着いた中間調で、手前で戦うアニメ塗りのキャラクターより目立たないように彩度と明度を一段落とす。文字・ロゴ・数字・キャラクター・人物は描かない。写真風・3DCG・ピクセルアートにしない。
```
各レイヤーの指定（例：STAGE 02 の L4）：
```
（共通の頭書き）
内容：将棋盤のような6×6のマス目がはっきり見える木の板。横長の帯状の足場パーツ。上端はまっすぐ水平で、そこが足場の天面。マス目は等間隔で、正面から見た盤の帯として描く。
出力：3600×360px、本当の透明背景。足場以外は何も描かない。
```
- 同じ形式で全ステージ×L1〜L7を作る（1レイヤー1生成。L6はL4の区画切り出しでもよい）。
- 生成のたびに、原画／全文プロンプト／生成日時／採否を `art_source/paper_stages/<stage>/` に保存（`.prompt.json`）。採用版を `イラスト確認/ステージ/<ステージ名>/` に日本語名で置き、候補と採用を区別する。

## 4. ゲームへの組み込み
- 専用 Editor ビルダー（手書きYAML禁止）で各 `StageData` のテーマにレイヤーを割り当て。L1/L2 は視差、L3 は画面固定、L4/L5 は地形の矩形に正確に合わせて配置（足場天面＝判定の天面）。
- 縮小：既存の区画タイミングで L6 の該当区画を紙演出（めくれ・倒れ・裏返り）で消す。予告点滅は維持。消え方は描画だけ、判定は既存どおり。
- 既存の Unity 図形版はフォールバックとして残す（画像が無いステージ用）。
- 3つの画面比率（16:9・16:10・4:3）で、足場と画面枠が切れない／キャラが隠れないこと。

## 白い切り抜き縁の品質（2026-10-15 ユーザー指摘）
- **原因（2026-10-15 確認）**：内蔵 image_gen に「透明背景で出力」させると、切り抜きの境目が柔らかい半透明（フェザー）で出ることがあり、白い縁の外側がぼやける（待機v2はたまたま硬く、ガードv1は柔らかかった）。
- **推奨の作り方**：透明背景で直接出させず、**肌色・クリーム白・衣装色から遠い単色の背景（純緑 #00FF00 または純マゼンタ #FF00FF、キャラの配色で選ぶ）で生成** → その色をキー抜き → **アルファを2値化**（α≥128→255、<128→0）→ 縁の色かぶり（緑/マゼンタのにじみ）を除去してクリーム白に揃える。人物画素は再サンプルしない。キー色・しきい値・処理前後を manifest に記録。
- 既存の採用絵（待機9人・千鶴・透真）も、縁の外側に半透明帯が残っているものは同じ2値化で直す（人物内部・線画は触らない。元画像は保持）。
- 白い縁は残す。ただし**ぼやけ・にじみは不可**（透真のガード v1 は縁が太く外側へグラデーションでにじんでいた。待機 v2 の細くくっきりした縁が基準）。
- 採用前の検査：縁の外側の半透明帯の幅を測り、待機 v2 と同程度（目安 2px 以下）であること。超える場合は作り直す。
- 作り直しが難しい場合の後処理：人物の画素は再サンプルせず、**外周の半透明画素だけ**を、アルファしきい値で2値化（例：α≥128→255、<128→0）し、縁の色をクリーム白に揃える。人物内部・線画には触れない。処理前後を保存し、処理したことを manifest に記録する。
