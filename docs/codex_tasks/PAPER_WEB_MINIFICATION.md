# 結衣のWeb確認中に見つけた人物の縮小時の欠け（2026-10-17）

rework_r4_yui_1は実Unity4工程全合格（555／73）。WebGL rework_r4_yui_webも実ビルド成功だが、739px幅の練習で結衣と蓮の人物が細かく欠けたように見える。旧シロのWeb撮影にも同じ症状あり。判定表示を消しても残り、1440px幅では緩和する。原画と512pxのネイティブ撮影は正常。エラーログ0でも視覚の合格としない。

原因候補は1304×1450の高精細な全身を小さく表示する際に、ミップマップなしでごく一部の画素だけを参照してしまう縮小のエイリアシング。Unity公式のミップマップ説明に従い、まずWebビルド専用の紙人物キャッシュに縮小表示用のミップマップとトリリニア補間を導入し、同じブラウザの同じサイズで前後比較する。未確認の段階で原因確定・修正完了と書かない。

原画・Unityの通常素材・Sprite.rect・支点・PPU・人物のワールド寸法は変えない。DXT圧縮のミップチェーンのためキャッシュの右と上だけを2の累乗へ透明梱包。背景／集合絵／旧ピクセルは現行方式を保持。元RGBAの保存、透明余白、実際の小さい描画での透明度の安定を検査する。既存の検査は弱めない。

実ブラウザで改善しなければ、この仮説の変更を本採用せず、次の原因を調べる。改善後に実Unity全4工程を新しいタグで再実行し、WebGLも再ビルド／実入力／撮影／console検査。結衣の採用記録・RESUME・STATUSへ最新の検証を記録して通常保存。全体の次はPAPER_KING_TWELVE_KEYS。

参考：[Unity公式：ミップマップ](https://docs.unity3d.com/jp/current/Manual/texture-mipmaps-introduction.html)、[Unity公式：GPUテクスチャ形式](https://docs.unity3d.com/ja/6000.0/Manual/texture-formats-reference.html)。

結果：同じ739px幅で人物の縮小のざらつきを軽減し採用。329キャッシュの元RGBA一致、2の累乗の余白は透明。Webは78.9MBへ増え、小さい表示は輪郭が柔らかくなる。rework_r4_yui_2で実Unity全4合格（557／73）。実ブラウザの前後比較はdocs/screenshots/rework_r4_yui_web/。元の紙素材・原画・支点・PPU・性能は不変。
