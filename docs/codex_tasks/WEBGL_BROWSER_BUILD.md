# ブラウザで遊べる版（Unity WebGL）を作る（2026-10-15、Claude記入・後日着手）

## ユーザーの依頼
> 後程 web でも気軽にできるようにしたい（＝ゲーム自体をブラウザで遊べるように）。

着手時期：ユーザーが指示したとき（「後程」）。現在の紙舞台・ポーズ制作の区切り後。同時編集禁止。
前提：Unity 6000.6.0f1 に **WebGLSupport モジュールはインストール済み**（`Editor/Data/PlaybackEngines/WebGLSupport`）。

## 1. ブラウザ版で問題になる点（先に調査・対応する）
1. **キーの衝突**：ブラウザが先に使うキーと重なる。F5（再読み込み）、F11（全画面）、Tab（フォーカス移動）、Esc（全画面解除）、Ctrl+W 等。現在の割り当て（練習の F5/F6/F7、判定表示 F9、全画面 F11、技表 Tab、ポーズ Esc）を **WebGL ビルドでは別キーに切り替える**（例：ポーズ P、技表 M、練習スロー 1/2/3 等）。`preventDefault` が効くキーと効かないキーを確認し、操作説明・チュートリアル・キーコンフィグの表記も WebGL 用に。
2. **音**：手続き生成の BGM/SE が `OnAudioFilterRead` 等の WebGL 非対応 API を使っていないか確認。WebGL では事前に `AudioClip.Create` で作った PCM か、生成済み WAV/OGG を使う。ブラウザはユーザー操作まで音を出せない（タイトルでのクリック/キー入力後に再生開始）。
3. **ゲームパッド**：ブラウザの Gamepad API 経由。DualSense/Xbox が `Gamepad` として認識されるか、PS 表記の自動判定がブラウザでも働くか（デバイス名が変わる可能性）を確認。
4. **容量と読み込み時間**：紙イラスト（1304×1450）が多数あるため、テクスチャの最大サイズ・圧縮（WebGL 向けの ASTC/DXT/ETC2 や Crunch）、Brotli/Gzip 圧縮、不要アセット（旧ピクセル素材・予備のカバン版等は**ビルドに含めない**だけで削除はしない）を整理。目標：初回ダウンロード 50MB 以下（目安）。
5. **性能**：WebGL はシングルスレッド。60Hz 固定 tick・描画補間・CPU AI がブラウザで落ちないか（フレーム時間を計測）。VSync/フレームレート設定は WebGL では `requestAnimationFrame` 任せになる点を考慮。
6. **保存**：PlayerPrefs（キーコンフィグ・音量）は IndexedDB に保存される。消えた場合の初期値復帰。
7. **画面**：ブラウザ窓のサイズ変更・全画面・スマホ表示（スマホのタッチ操作は対象外と明記し、PC＋キーボード/パッド向けとする）。
8. **ファイルIO・スレッド・リフレクション**：`System.IO` の書き込み、`Thread`、IL2CPP で消える型（コード stripping）を使っていないか。必要なら link.xml。

## 2. 実装
- WebGL 用のビルドメニュー／コマンド（`ProjectBuilder` に WebGL ビルドを追加、`-buildTarget WebGL`）。出力先 `Build/WebGL/`（容量管理ルールの対象）。
- WebGL 専用のキー割り当てプリセットと、起動時に WebGL なら自動適用。
- ローカル確認：`tools/verify/` に WebGL ビルドを配信する簡易サーバー（Brotli の Content-Encoding を正しく返すもの）と、ブラウザでタイトル→対戦→リザルトまで動くことを確認する手順。
