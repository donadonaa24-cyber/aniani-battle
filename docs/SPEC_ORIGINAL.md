# あにあにバトル！！（略称：あにバト！！） 開発・実装指示書（原本）

> 正式タイトル：**あにあにバトル！！**　略称：**あにバト！！**
> （旧企画仮称「ANIANI ALL-STARS」は廃止。以下の原文中の仮称はこの正式名称に読み替えること）
> 役割分担：**Codex＝メイン開発**（Unityプロジェクト構成、戦闘ロジック、キャラ操作、当たり判定、CPU、テスト）／**Claude＝レビュー・改善・進捗取りまとめ**

## 0. 役割と最終目標

複数のゲーム・小説のキャラクターが共演する、オリジナル2D横スクロール対戦アクションゲームを開発する。
参考ジャンルはスマブラなどのプラットフォームファイターだが、戦闘ルールは独自。既存ゲームのソースコード、固有UI、アセットを模倣せず独自作品として開発する。

**最終目的は企画書ではなく、実際にWindowsで遊べるUnityゲームを完成させること。**

開発環境：Windows 11 / Unity 6000.6.0f1 / Blender / Git / Codex・Claude

既存の『Battle à la carte』『推し駒Battle』などのプロジェクトを破壊、上書き、混在させない。
ユーザーの許可なくコミット・push・公開・既存ファイルの破壊的削除はしない。
確認が必要なのは、既存データ破壊・外部公開・有料サービス・認証情報・不可逆な変更など。

# 1. ゲームのコンセプト

* 2D横スクロール / 超高速アクション / 1対1基本
* 1試合70秒
* 初期ハート3個
* 通常攻撃の被弾3回でハート1個減少
* 特殊攻撃の命中でハート1個減少
* 超必殺技の命中でハート2個減少
* ステージ外への落下で即敗北
* 最大3ヒットコンボ
* ガード、回避、カウンターによる読み合い
* 60秒経過後、残り10秒間でステージ縮小
* キャラクター固有スキル
* 将来的なサポートキャラ選択
* 作品別ステージ

操作は初心者でも分かりやすく、上級者には攻撃の優先順位やタイミングの読み合いがあるゲーム。

# 2. 初期プレイアブルキャラクター（3人）

### ① 透真（出典：小説『星の終わりに君は生きる』）
戦闘方針：解析、防御、カウンター、機動力を活かすテクニカルタイプ。
* 通常必殺技：観測パルス
* 横必殺技：遮断ステップ
* 上必殺技：緊急上昇
* 下必殺技：防御・妨害技
* 超必殺技：境界突破
* カウンター固有効果：成功後の移動性能または反撃性能を一時強化

原作に存在しない超能力を勝手に正史設定にしない。SF的な戦闘装備や演出は本作専用のクロスオーバー表現として扱う。

### ② 蓮（出典：『推し駒Battle』）
戦闘方針：高速移動、直線的な突進、攻撃特化。原作の将棋風移動、飛型、直線番長などを参考。
* 通常必殺技：飛車ライン
* 横必殺技：直線番長
* 上必殺技：縦抜け
* 下必殺技：構え・急襲系
* 超必殺技：十字突破
* カウンター固有効果：成功時の吹っ飛ばし距離増加

### ③ 千鶴（出典：『Battle à la carte』）
戦闘方針：料理を利用した中距離、変則攻撃、自己回復。
* 通常必殺技：爆弾おにぎり（命中した相手がおにぎりを食べてしまい短時間麻痺。操作不能時間は長すぎないこと）
* 横必殺技：フライパン突撃
* 上必殺技：おたま旋風
* 下必殺技：食事による自己回復（まず通常攻撃の被弾蓄積を1減らす効果。ハート回復はバランス調整後に検討）
* 超必殺技：満腹カレー！
* カウンター固有効果：成功すると自分の通常攻撃被弾カウントを1回復（調整可能）

キャラクターの容姿、性格、設定は元作品を尊重する。
参考ポータル：https://donadonaa24-cyber.github.io/aniani-asobiba/ （ローカル：`%USERPROFILE%\\OneDrive\デスクトップ\あにあにの遊び場`）
調査できなかった設定を勝手に原作設定として確定しない。
画像・モーション不足時はキャラごとに識別可能な仮Spriteを生成し、ゲーム実装を先に進める。

# 3. 戦闘の基本ルール

## 3-1. ハートシステム
各プレイヤーはハート3個で開始。0で敗北。HP100などの数値制は採用しない。

## 3-2. 通常攻撃
通常攻撃はガードできない。被弾すると被弾カウント+1。
* 0/3：蓄積なし / 1/3 / 2/3 / 3/3：ハート1個減少、その後0/3へ戻る

被弾カウントはコンボが途切れても保持。時間経過、移動、ジャンプ、ガードでは回復しない。特殊攻撃を受けても保持。スキルによる回復でのみ減る。

### 頭上カウンター
被弾カウントをキャラ頭上に `0/3`、`1/3`、`2/3` で表示。
* 1/3で軽い反応 / 2/3で黄色・オレンジ等の警告色 / 3ヒット到達でBREAK演出 / ハート減少後0/3へ
* キャラの移動、ジャンプ、吹っ飛びに追従
* 画面上部HUDにも被弾数を表示（画面外でも確認可能）

### 最大3ヒットコンボ
* 連続コンボは最大3ヒット
* 通常攻撃3連続ヒットでハート1個減少＋大きく吹っ飛ばす
* コンボ3ヒット到達後は一定時間、同じ攻撃側から追撃不可
* 別々の機会に当てた累計3ヒットでもハート1個減少。ただし大きなコンボフィニッシュ演出は連続3ヒット時のみ
* コンボ連続判定時間、吹っ飛ばし量、追撃禁止時間はデータで調整可能

**暫定安全策：** 同一コンボ中に減少するハートは基本最大1個（超必殺技は例外）。意図せず3ハート即消滅しないこと。

## 3-3. 特殊攻撃（必殺技）
* 命中でハート1個減少 / 通常ガードで防御可 / 回避で回避可 / 基本カウンターに勝つ
* キャラごとに性能が異なる / ゲージ不要
* 発生、射程、移動量、硬直、吹っ飛ばし、追加効果で差別化

## 3-4. 超必殺技
作品リンクゲージを使用。
* 命中でハート2個減少
* 通常ガードで防御不可 / 通常回避の無敵だけでは防御不可
* ジャストガード、ジャスト回避で防御可能
* 攻撃範囲外へ移動すれば命中しない
* 空振りで大きな硬直
* キャラ固有のカットイン・演出
* 初期版では1試合に最大1回

70秒でも実際に使えるゲージ獲得量に調整。被弾側にもゲージをためる手段を設け逆転の可能性を残す。

# 4. 防御と読み合い

基本行動：通常攻撃 / 特殊攻撃 / ガード / 回避 / カウンター / 超必殺技

## 4-1. 行動の相性
* 通常攻撃 → ガードに勝つ
* 回避 → 通常攻撃を防ぐ
* カウンター → 近距離通常攻撃に勝つ
* 特殊攻撃 → カウンターに勝つ
* ガード → 特殊攻撃を防ぐ
* 超必殺技 → ジャストガードかジャスト回避で防ぐ

通常攻撃は原則ジャストガードでも防げない（将来のキャラスキル例外は可）。

## 4-2. カウンター（全キャラ共通）
* 近距離通常攻撃に対応 / 成功時は被弾無効化
* 相手へ通常攻撃1ヒット分の被弾カウントを返す
* 相手を少し弾いて距離を作る / 無限追撃不可
* 失敗時は隙 / 特殊攻撃・超必殺技・遠距離通常攻撃には基本無効
* カウンターと近距離通常攻撃が同時接触した場合、受付中のカウンターを優先
* キャラ固有の追加効果を設定できる構造

## 4-3. ジャストガード
特殊攻撃・超必殺技が命中する直前の短時間にガード。成功時：ダメージ無効、特殊エフェクト、小さな反撃機会、ゲージ増加。
通常攻撃は通常ガード・ジャストガードともに原則防御不可。

## 4-4. ジャスト回避
攻撃が当たる直前のタイミングで回避。成功時：被弾無効、短い演出、反撃機会、ゲージ増加。
超必殺技の防御判定は通常回避とジャスト回避を区別。
ジャスト受付は60fps基準4〜6F仮設定、変更可能に。

## 4-5. キャラスキル（将来）
通常攻撃の一時ガード可能化、蓄積回復、ジャスト回避強化など。時間制限または回数制限を設け、基本相性を崩さない。

# 5. 移動と操作

超高速。実装：左右移動、高速ダッシュ、ジャンプ、2段ジャンプ、空中ダッシュ、急降下、空中攻撃、ガード、回避、カウンター、被弾吹っ飛び、空中復帰。
ステージ端から端までのダッシュ時間 約2〜3秒。

| 入力 | キーボード |
| ---- | ---- |
| 左右移動 | A / D |
| ジャンプ | Space |
| 通常攻撃 | J |
| 特殊攻撃 | K |
| ガード | L |
| 回避 | Shift |
| カウンター | I |
| 超必殺技 | U |
| ポーズ | Esc |

ゲームパッド対応。方向キー＋特殊攻撃で通常・横・上・下の4種必殺技。
キー配置は調整可、操作説明画面に表示。同時押しの優先順位を明確に。入力状態と戦闘状態を分離。
（ローカル2人対戦用に2P側キー配置も別途定義すること）

# 6. ステージ

* STAGE 01：星の終わり — 管理AIが支配する近未来都市（青、紺、電子的な光、未来建造物）
* STAGE 02：推し駒Battle — 原作の6×6盤面をイメージした闘技場（巨大な駒、盤面、階層塔）
* STAGE 03：Battle à la carte — 文化祭の調理場（料理、屋台、調理道具、文化祭装飾）

### 共通地形（3ステージ同一）
* メイン足場1つ / 上部の小さな足場2つ（下から通り抜け可能）
* 左右と下側の場外判定 / ジャンプや上必殺技による復帰 / 場外判定を越えたら即敗北
* 固有ギミックなし。背景・色調・BGM・床の見た目のみ作品ごとに変更

### ステージ縮小
* 残り10秒（開始60秒後）で縮小開始。縮小前に視覚的警告
* 左右の床が徐々に消え、最後は中央の小さな足場のみ
* 全ステージ同じタイミング・当たり判定
* キャラ位置と床の関係を考慮、理不尽に突然消さない
* 背景演出：星の終わり＝AI警告・電子的消失 / 推し駒＝盤面外側のマス消失 / à la carte＝文化祭終了演出
* 縮小は共通ルール。背景固有ギミックとは分離
* 将来の昼・夕・夜差分に対応できる構造（初期版不要）

# 10. 技術設計

Unity 2D。Blenderは必要時のみ。3D格闘にしない。

主なシステム：GameManager, MatchManager, FighterController, FighterStateMachine, InputController, CharacterData, AttackData, Hitbox/Hurtbox, DamageSystem, ComboSystem, GuardSystem, DodgeSystem, CounterSystem, SkillSystem, SpecialMoveSystem, UltimateSystem, GaugeSystem, StageManager, StageShrinkController, CameraController, CPUController, HUDController, AudioManager, SupportSystem（拡張用）
名称・分割は変更可。巨大な1スクリプトにしない。
性能、発生フレーム、硬直、射程、移動速度、吹っ飛ばし、状態異常時間などはScriptableObject等で変更可能に。

### 戦闘処理
* 60Hz固定更新で一貫した戦闘処理
* フレーム依存バグ、入力取りこぼし、多重ヒットを防止
* ヒット対象と攻撃IDを管理
* 状態：Idle / Move / Dash / Jump / Fall / Attack / Special / Guard / Dodge / Counter / Hitstun / Knockback / Recovery / KO
* 移動、アニメーション、攻撃判定、ダメージ管理、UI更新を分離
* 将来のオンラインに備え戦闘処理と入力取得を分離（ネットコード実装は不要）

### アニメーション（初期）
待機、移動、ダッシュ、ジャンプ、落下、通常攻撃、特殊攻撃、カウンター、ガード、回避、被弾、吹っ飛び、勝利、敗北。正式画像不足時は仮画像・仮アニメで成立させる。見た目に時間を使いすぎない。

# 12. 必須テスト

1. 通常攻撃1回で1/3
2. 通常攻撃2回で2/3
3. 通常攻撃3回でハート1個減り0/3
4. コンボが途切れても蓄積保持
5. 特殊攻撃を受けても通常攻撃蓄積が消えない
6. 3連コンボで大きく吹っ飛び、直後の追撃が成立しない
7. 通常攻撃はガードを通過
8. 特殊攻撃はガードで防げる
9. カウンターが近距離通常攻撃に勝つ
10. カウンター失敗時に適切な隙
11. カウンター成功で相手の通常攻撃蓄積が1増える
12. 超必殺技命中でハート2個減る
13. 超必殺技は通常ガードで防げない
14. ジャストガード・ジャスト回避で超必殺技を防げる
15. 場外判定で即敗北
16. 70秒制限時間が正常
17. 残り10秒でステージ縮小開始
18. 残り0秒で正しく勝敗判定
19. 3キャラとも操作可能
20. CPU戦が成立
21. ローカル2人対戦が成立
22. リザルトから再戦可能
23. 頭上カウンターが正しく追従
24. 連続攻撃や高フレームレートでも被弾数の二重計算なし

時間切れ：残りハートが多い側 → 同数なら通常攻撃被弾蓄積が少ない側 → 完全同数なら引き分け（暫定）。
同一更新タイミングでの落下と時間切れなど、勝敗判定の優先順位を明確に。
Unity Test FrameworkでEditMode / PlayModeテストを用意。

# 16. 作業方針
仕様書作成で止まらず実装・検証・修正を段階的に進める。未確定事項は確定仕様と矛盾しない暫定値を設定し変更しやすく。

最重要仕様：70秒の超高速勝負 / ハート3個 / 通常攻撃の3ヒット蓄積 / 頭上被弾カウンター / 最大3ヒットコンボ / 3コンボ後の大吹っ飛びと追撃禁止 / 通常攻撃はガード不可 / 特殊攻撃はガード可能 / カウンターは全キャラ共通 / 超必殺技はハート2個 / ジャスト防御による逆転 / 場外即敗北 / 最後10秒でステージ縮小

優先順位：**遊べること ＞ 戦闘の気持ちよさ ＞ ルールの正確性と安定性 ＞ UI完成度 ＞ キャラ演出 ＞ 背景の豪華さ**

仕様に反する未完成状態を完成と偽らない。各フェーズ終了時に実装内容・確認結果・残課題を報告。中断しても再開できるよう進捗資料を更新。
