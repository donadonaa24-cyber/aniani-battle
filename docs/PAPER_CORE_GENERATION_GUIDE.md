# 基本5ポーズの再現と引継ぎ

各キャラは全身1枚絵のガード・しゃがみ・カウンター・勝利・敗北。共通の方針はPAPER_THEATRE_DIRECTION.md、人物ごとの条件はart_source/paper_roster_core/<key>/prompts/。対象8人と既存千鶴を混同せず、progress.jsonで生成とUnity接続の済んだ人を確認する。

1. 原画と採用版をmanifestで確認。透真の基準は待機v2。描き直すときは新しい版番号と全文条件を保存し、採用中の原画を上書きしない。
2. 直接の画像生成入力は本人の採用待機。千鶴の同じ動作と元作品資料は事前の容姿／画風確認用。複数人の参照を直接混ぜると透真の体格が約8%縮んだため、同一人物の実寸維持を優先して入力を絞った。別の構図や高い頭身に戻さない。
3. 頭・髪・靴・手の実寸を固定し、低姿勢を画面いっぱいに拡大しない。共通枠が一致するだけでは合格にしない。part-review.jsonと等倍／一覧を比較し、概算である数値は正確な自動測定と呼ばない。画面左右と本人の左右を分け、肩→肘→手首→親指を確認する。四足のシロは四足のまま、蓮は肉球ミトン、結衣の杖は本人左手、湊の義腕と機械の目は本人左側。
4. 内蔵image_genで1姿勢につき1回生成。同じ人物の独立したポーズは並列に呼び出せるが、次の人物へはその人の5種類を揃えて審査してから進む。保存とmanifest更新は逐次行う。真の透過、全身、薄いクリーム白の硬い縁、グローなし。今回は通常のアニメ塗りで、旧224×160ピクセル素材や32色パレットへ縮小しない。キャラの紙質や関節パーツ化を追加しない。
5. 外周ぼやけはPAPER_ROSTER_CORE_POSESの明示手順に沿いアルファしきい値128で2値化。生成前の原画をgenerated、処理後をedge_cleanへ別保存。RGBと完全不透明の内部画素は変えず、人物の再サンプルをしない。元RGBAとの完全一致ではなく、処理済み画像の画素一致／倍率維持として記録する。
6. 透明余白で1304×1450、足元1328へ。人物を切る場合は停止して再審査する。PPU532.5893、中央の足元支点。ゲーム側はPaperRosterCoreBuilderで生成し、手書きYAMLを使わない。未制作の透真／蓮の動作は旧素材、追加6人は待機1枚の簡易変形を継続する。
7. 今回は透真を先行の実Unity全4工程で保存後、残り7人の原画を人物単位で揃え、一括接続して実Unity全4工程。左右・実入力・ポーズ解除・勝敗を確認し、docs/screenshots/paper_core_<key>/へ実Camera.Renderを保存する。実モニター撮影ではなくOSキーを送らない。OS撮影スクリプトを使う場合は別途「PCに触らないで」と先に伝える。
8. 全合格後に確認用フォルダをゲーム採用済みへ変更し、STATUS／RESUME／実装順を更新、通常commit・push。絵の最終承認とゲーム採用を区別する。

## 補助スクリプト

Sharpを使えるNodeでtools/verify/paper_core_generation.cjsを実行。initは未作成の計画のみを作り、既存原画を生成し直さない。begin <key> <pose>は保存済み原画があれば拒否する。begin後に内蔵ツールで生成し、captureはその1回に増えたPNGが1つだけのときに原画を保存する。別チャット／別担当ではPAPER_CORE_IMAGE_DIRへその回の内蔵ツール出力フォルダを設定する。pending-job.jsonは一時ファイルでGit管理外。

同じ人の複数ポーズを生成するときはjob <key> <pose>で読み取りのみ行い、各ツール結果のoutput_hintに返る保存PNGをsave <key> <pose> <出力PNG>へ逐次渡す。出力フォルダの更新時刻から割り当てを推測しない。保存元は内蔵ツールのgenerated_images配下に限定する。並列呼び出しで1件が失敗しても成功した原画は保存して、失敗したポーズだけ再開する。

prepare <key>は透明梱包と確認一覧、runtime-manifestを更新する。全4工程が合格してからprepare <key> <検証タグ>で採用状態にする。タグを渡すだけではUnityを実行したことにはならない。確認中フォルダを作業領域内で安全に改名し、古い候補との二重表示を避ける。修正版の新しいpromptとmanifestのjobsを更新してから再試行する。千鶴のカバン版は保護対象で、このスクリプトでは削除しない。

## 2026-10-16の実作業で確認した落とし穴

- 出力の縦横サイズを指定しても、生成ツールが1189×1323／1103×1426／1254平方などの原画を返すことがある。枠だけを理由に拡縮せず、部位寸法・切断・しゃがみ全高を審査し、透明余白で共通枠へ入れる。人物が切れるとprepareは失敗する。
- 膝を曲げると頭や靴が大きくなりやすい。待機の部位幅と原画内の透明上余白を数値で指定し、必要なら局所編集する。全身の倍率変更で帳尻を合わせない。暁crouch v3／龍太crouch v2の全文条件も参照。
- OneDrive側の一時UNKNOWNエラーでは、コピー済み原画があってmanifestだけ未更新のことがある。同一ツール出力とSHAが一致するときだけsaveを再実行して記録を復旧できる。別原画の上書きは拒否。read／writeは対象の一時エラーのみ短く再試行し、失敗を握りつぶさない。
- check_paper_core.cjsは選定40枚の原画SHA・RGBと不透明内部・外周アルファ・梱包画素・足元1328としゃがみ高さを独立照合する。pixel-audit.jsonは絵の最終承認や実Unityの代用ではない。
