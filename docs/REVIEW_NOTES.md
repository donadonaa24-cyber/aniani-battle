## 2026-10-12 ユーザー報告：「カクつく」（最優先で対応）
調査結果（Claude）：
- ユーザーのモニターは **144Hz**（RTX 3060 Ti）。戦闘シミュレーションは60Hz固定。
- **描画が tick 間を補間していない**（`FighterView` が `fighter.Position` をそのまま `transform.position` に代入。`FixedTickClock.Fraction` は未使用）。144Hz では1 tickの位置が2〜3フレームずつ不均一に表示され、移動がガタつく（ジャダー）。弾・カメラ追従・頭上カウンターも同様。
- **スプライトのアニメが少ないコマ数・低fps**（攻撃 3〜4コマ/10fps、落下 2コマ/8fps、ガード 2コマ/6fps など）。動きのパラパラ感の主因。
- ポリゴン数・描画負荷が原因ではない（2Dスプライトで負荷は極小）。3D化してもジャダーは直らない。
対応（フェーズ5完了直後に最優先で実施）：
1. **描画補間**：各 tick で前回位置を保持し、描画は `Lerp(前tick, 現tick, clock.Fraction)`。シミュレーションは変更しない（決定性維持）。キャラ・弾・エフェクト・頭上カウンター・カメラ目標に適用。ヒットストップ／テレポート的な移動（リスポーン等）では補間しない。
2. VSync を有効（モニター同期）にし、`Application.targetFrameRate` は -1（VSync任せ）。設定で 60/120/144/無制限を選べると良い。
3. アニメのコマ追加：主要アニメ（walk/dash/attack1-3/special/jump/fall）を 6〜8コマ・12〜15fps 程度に増やす（SpriteForge で中割りを生成）。攻撃は発生・持続・硬直の進行度同期を維持。
4. 確認方法：144Hz環境でダッシュ往復・ジャンプをスクショではなく**フレーム時間の計測ログ**（描画位置の差分の均一さ）で検証するテストを追加。
